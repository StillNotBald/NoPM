Login identity and work identity are born together — never two rows that can point at different people.

Confirmed absence, shown honestly: no invite or acceptance email is sent — the one-time link is returned in the API response for manual sharing, and the first agent token is a deliberate manual mint, never auto-granted at signup.

Why it holds

  • Login identity and work identity are the same foreign key from the moment of acceptance — never two rows that can drift apart.
  • Role cap prevents privilege creep at invite time — a manager cannot mint an admin invite.
  • Connecting an agent is always a deliberate, separate, manually-scoped action — never bundled into signup.
