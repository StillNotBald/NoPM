# GET /api/export

Governed CSV export. One audit row (`export.csv`, with the entity, row count and filters) is written for every download.

## Entities

| entity | who can export | notes |
|---|---|---|
| tasks, risks, issues, clashes, audit, programs, projects | token or session holding the entity's read scope (`task:read`, `risk:read`, ...) | filters mirror each list API |
| change_requests | token or session holding `change:read` | id, ref, project, title, category, status, priority, raised/decided dates, requester and decider (name and principal id), decision (approve / reject / defer) and note, impact (days, cost, scope), implemented date and person, evidence counts (total, pass, fail, latest), linked decisions. Date range: raised, decided or implemented in range (or `updated_at` with `on=updated`). The implemented and evidence columns are blank until those fields are recorded. |
| members | admin or manager **session** only | profile, role, status, `mfa_enabled`, `removed_at`, last role change (from audit). Same audience and email field as `GET /api/members`. |
| tokens | admin or manager **session** only | `label`, `prefix`, `scopes`, creator, `expires_at`, `revoked`, `last_used_at`. Never the token hash. The assistant's per-turn tokens are hidden, as in the tokens list. There is no `revoked_at` column, only the `revoked` flag. |
| identities | admin or manager **session** only | chat-connector links: profile, provider, `linked_at`, `revoked_at`. The external platform user id is not exported. |

A token, a member or a viewer gets 403 on `members`, `tokens` and `identities`, whatever scopes the token carries.

## Audit pack (`entity=audit_pack`)

`GET /api/export?entity=audit_pack&from=YYYY-MM-DD&to=YYYY-MM-DD&format=csv|pdf` (default csv)

One artefact for an external auditor. **Admin or manager session only**: a token (any scopes), a member or a viewer gets 403. Audited as `export.audit_pack` with the format, row counts and the range.

- A change request is included when it was **raised, decided or implemented** inside the range (no range = all). Dates are UTC days, both inclusive. `entity=change_requests` uses the same rule when `from` / `to` are given (with `on=updated` it filters on `updated_at` instead).
- The audit-trail section lists every `change_request.*` audit row for the SELECTED requests, not limited to the range (the decide row of a request implemented in the range is older than the range).
- If the database is older than migrations 0093/0094, the evidence and decision-link sections say `not available (schema older than 0093/0094)` instead of showing none.
- **CSV**: one file with a `section` column. Sections: `change_requests` (the columns above), `evidence` (documents attached to those requests: type, result, tester, date, note), `decisions` (decisions linked to those requests, plus decisions created in the range), `approvals_audit` (the `change_request.*` audit rows of the selected requests: action, actor, principal, time). Columns that do not apply to a section are blank.
- **PDF**: cover (workspace, range, generated at, generated by, counts), change-request table, evidence appendix per request, audit trail.
- Each section is capped at 10,000 rows; a truncation note is added and logged.
- Reads tolerate databases that do not yet have the evidence and implementation columns: those cells are blank (not recorded).

## Date range (every entity)

- `from` and `to` are UTC calendar days, both inclusive (`YYYY-MM-DD`). A malformed day is ignored.
- By default the range filters on `created_at`. Add `on=updated` to filter on `updated_at` for entities that have one (tasks, risks, issues, clashes, projects). Other entities keep their creation column (`linked_at` for identities).
- The range is recorded in the `export.csv` audit row.

## Audit CSV columns

`id, workspace_id, actor_type, actor_id, actor_label, action, target_type, target_id, before, after, channel, request_id, created_at, principal_id, principal_label, via_connector_id, external_event_id, external_actor_ref`

`principal_id` is the accountable person behind a token or connector action. `principal_label` is resolved from profiles in one query per export (blank when the person is unknown or it is a system action).

## Cap

At most 10,000 rows. If more match, the last line is `# TRUNCATED: showing N of M matching rows (cap 10000)` and a server warning is logged. Narrow with `from` / `to`.
