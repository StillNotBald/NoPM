## Release order

1. Apply migrations 0092, 0093, 0094 (in order) to the database. All three are additive: nullable columns, `add column if not exists`, indexes, CHECKs added `NOT VALID` or on new empty columns. The old build keeps working on the migrated database: it never reads or writes the new columns, nothing sets status `implemented`, and no backfill runs so no `updated_at` trigger fires.
2. Deploy the new build. It must not go first (W2-05): create-request, create-decision and create-document paths 500, and the Change Control and Decisions pages fail.
3. Run the wave-2 database rehearsal (W2-06) before or immediately after step 1.

## Verified OK

- **0092 idempotent and additive.** `add column if not exists` for all 8 columns; constraints guarded by `pg_constraint` lookups; `cr_implemented_after_decision` (`implemented_at is null or (decided_at is not null and implemented_at >= decided_at)`) and `cr_implemented_status_stamp` (`status <> 'implemented' or implemented_at is not null`) are NOT VALID then validated inside per-constraint `exception when others` blocks (0092 lines 52-90). No backfill, no `disable trigger`.
- **0092 RPC.** Exactly one `create or replace function nopm_implement_change_request` (new name, no earlier overload anywhere in `migrations/`). Single plpgsql body, so the status update and the single `insert into audit_log` are one transaction. Order: channel check, principal check (P0006), row `for update` in the caller's workspace (P0002), then who-may (admin/manager via `profiles` in the same workspace, or `requested_principal_id`, or `requested_by`, P0023), then already-implemented (P0028), then not-approved (P0024). Compare-and-set is by row lock plus status test. Audit row carries `before = to_jsonb(cr)`, `after = to_jsonb(v_after)`, channel, request id, connector id, external event and actor ref, and `principal_id`, matching `nopm_decide_change_request` (0072:343-427). Execute revoked from public/anon/authenticated, granted to `service_role`. P0028 is used nowhere else.
- **0092 vs existing checks.** `cr_maker_checker` (decider present and differs from requester) and `cr_principal_distinct` are untouched by the update, so approved rows pass when moved to implemented. Edit and delete stay refused for implemented rows (`change-requests/[id]/route.ts` `assertStillOpen`).
- **0093 and 0094.** Idempotent, additive, FK `ON DELETE SET NULL`, partial indexes, array/enum CHECKs on new columns only, so no existing row can violate. "A result needs a type" CHECK present. No `updated_at` trigger touched.
- **Implement route** (`change-requests/[id]/implement/route.ts`). `requireScope change:write`, `requirePrincipal` before the RPC (ownerless token gets 403 `no_principal`), workspace comes from `actor.workspaceId`, errcodes mapped to 403/404/422 in `lib/governance/implement.ts`. 10 route tests cover requester, manager, stranger, viewer, ownerless token, token owned by requester, wrong status, repeat, unknown/foreign id, long note.
- **Evidence listing** is workspace-filtered twice (request lookup, then documents `.eq("workspace_id")`), 404 for another workspace's request, scope `document:read`.
- **New list routes** (`/api/change-requests`, `/api/decisions`): `requireScope` change:read / decision:read, query always `.eq("workspace_id", actor.workspaceId)`, bad `project_id`/`status` is 422, limit capped at 100. `fields=` is validated against `FULL_COLUMNS`, which holds no secret columns (no `requested_principal_id`, no principal ids, no `storage_path`). `parseListSelection` rejects unknown names with 422.
- **`get_evm`** requires `budget:read` (already in the assistant ceiling); project and budget reads filtered by workspace; derived, nothing stored. The assistant ceiling gains only `decision:read` and `document:read`.
- **Audit pack access.** `assertCanExportAuditPack` runs first in `GET`, before any query: any token (`actor.type !== "user"`), member or viewer gets 403. Tests loop the cases and assert nothing was read (`audit-pack.test.ts:191-205`). Audit pack reads `audit_log` without `before`/`after`.
- **Audit coverage.** Implement writes exactly one row inside the RPC; document create/update keep their single `document.create`/`document.update` row with the full row in `after` (so evidence fields and `change_request_id` are included); decisions keep theirs. `export.audit_pack` is written once with format, row counts, truncation and range. Glossary has `change_request.implement` and `export.audit_pack`. `web/src/lib/audit/coverage.test.ts` is unmodified in the working tree.
- **Seams compile and agree.** `tsc` is clean. `change-detail.tsx` has one `EvidencePanel` import and mount line (W2-B) beside W2-A's `ImplementPanel` and `AREA_LABELS` import; no duplicate imports. `views.ts` carries W2-A's columns inside W2-D's new entity entries consistently. Evidence result values written by W2-B (`pass|fail|partial|n/a`) are matched by W2-C (`isPass`/`isFail` accept pass and fail). `profileLabels` moved to `lib/export/audit-pack.ts` is re-imported by `export/route.ts`; members, tokens, identities and audit callers use the same implementation (chunking by 100 was already the same constant), and existing export tests pass.
- **Rendering.** `renderAuditPackPdf` returns bytes for an empty and a populated pack and paginates a long register (3 tests). CSV `section` column approach is documented in `export/README.md`.
- **Mobile.** Audit pack panel, implement button and evidence rows use full-width controls at phone width (code read; not rendered in this review).
