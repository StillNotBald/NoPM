# W3-A handover RTM rows (R-140)

## REQUIREMENTS.md bullets

- **R-140** Handover / key-person report (audit gap M6, "runs without you"). Projects, risks, issues and tasks can each name a backup, and a report shows what would stall if one person were away. Acceptance: (a) migration 0095 adds nullable `backup_owner_id` (to `profiles`) on `projects`, `risks`, `issues` and `backup_assignee_id` (to `resource_members`, the same identity as `tasks.assignee_id` since 0019) on `tasks`, each `on delete set null` with a partial index, plus a CHECK on each table that the backup differs from the owner or assignee (added NOT VALID, then validated in a skip-on-failure block); no backfill and no trigger touched, so no `updated_at` moves; (b) the create and update routes for projects, risks, issues and tasks accept the field, check the person belongs to the caller's workspace (422 `invalid_reference` otherwise), refuse a backup equal to the owner or assignee as stored or as sent (422 with the field named), and carry it in the audit row `after`; a PATCH that omits it leaves it unchanged and an explicit null clears it; (c) `web/src/lib/api/views.ts` adds the column to the summary and full lists of all four entities; (d) GET `/api/reports/handover[?project_id=][&format=json|csv]` needs `project:read`, `risk:read`, `issue:read` and `task:read`, filters by `actor.workspaceId`, and returns per project the open items (project not complete, risk not closed, issue not resolved or closed, task not completed or canceled) whose owner has no backup, grouped by owner with counts, the open items with no owner, and a workspace key-person matrix per person with items solely owned, projects touched, items backed up for others and a `bus_factor_1` flag (true when they solely own any open item); a resource member linked to a login counts as that login; a foreign `project_id` is 404 and a malformed one 422; (e) `format=csv` returns the same data as one CSV through the CSV helper and writes one `export.csv` audit row with entity `handover`; (f) MCP and assistant tool `get_handover_report` (optional `project_id`, read scopes only, GET only); (g) console page `/handover` (stacked cards at phone width, CSV export link, nav entry in the Portfolio section), a "No backup owner" badge on the project header, and a Backup owner or Backup assignee picker on the project, risk, issue and task forms that sends the field only when the person changed it (so a form that did not load the stored backup can never clear it). Migration 0095 applies before the build serves traffic: `views.ts` selects the new columns unconditionally on the list and detail routes. Outcome: presentable multi-project and easier reporting. — **DONE** (migration, routes, report, tool, page, badge and forms shipped in wave 3; OpenAPI and llms.txt entries applied by the docs agent per `rtm/w3a-openapi-notes.md`)
