# W4-C1 atomic audited writes RTM rows (R-152)

## REQUIREMENTS.md bullets

- **R-152** Atomic audited writes (audit gap M1; owner answer Q-GOV-23 "all-or-nothing"). A change and its audit row succeed or fail together; the previous handlers wrote the change first and the audit row afterwards, so a failure in between left a change the trail never saw. Acceptance: (a) migration 0103 adds `nopm_mutate_audited(p_table, p_op, p_workspace_id, p_id, p_patch, p_expected_updated_at, p_audit)`, one overload, `security definer`, pinned `search_path`, executable by `service_role` only: it checks the table against an explicit allowlist (the governed tables plus `project_dependencies` and `task_dependencies`), checks every patch key against `information_schema.columns` (`UNKNOWN_COLUMN`), refuses `id`, `workspace_id` and `created_at` in a patch, quotes identifiers with `format('%I')`, writes through `jsonb_populate_record`, matches rows on the caller's workspace (no row: `NOT_FOUND`), compares `updated_at` to the caller's value in milliseconds (`STALE_ROW`, mapped to 412), returns the row before and after, and inserts exactly one `audit_log` row in the same transaction with the same actor, channel, request id, principal and connector provenance as `writeAudit`; optional audit controls (omit secret columns from the audit row and the returned rows, override the recorded before, after or target, add context to the recorded after, compare-and-set on a nullable column); (b) `web/src/lib/audit/audited-write.ts` wraps it as `auditedInsert`, `auditedUpdate` and `auditedDelete`, maps `NOT_FOUND` to 404 and `STALE_ROW` to 412, logs and answers a generic 500 for a rejected table, column or operation, rethrows any other database error unchanged, and builds the audit payload with the same row builder as `writeAudit` (now in `audit/row.ts`); fail-closed: when the function fails nothing was written; (c) route group 1 is converted with unchanged request and response contracts, status codes, 412 semantics and side effects: projects (POST, PATCH), project tasks, milestones, risks, issues and expenses (POST), tasks (PATCH), milestones, risks and issues (PATCH), clashes (POST, PATCH, DELETE), programs (POST, PATCH, DELETE), sprints (POST, PATCH, DELETE, start, task attach and detach), allocations (POST, PATCH, DELETE), resources (POST, PATCH, DELETE), saved views (POST, PATCH, DELETE, duplicate), calendar feeds (create, revoke; the token hash is never read back or audited), project dependencies (POST, DELETE) and task dependencies (POST, DELETE); (d) still non-atomic and listed with reasons in `atomicity.test.ts`: the project and task DELETE handlers (they insert a `deletion_requests` row, then audit; need their own function), change-request raise and rebaseline draft (approval-tier wave), and the five DELETE handlers of risks, issues, expenses, documents and milestones (deletion-flow wave); (e) `coverage.test.ts` counts a call to the wrapper as audited, `action-glossary.test.ts` reads actions from wrapper calls, and `atomicity.test.ts` fails when a group-1 handler calls `writeAudit(` after a direct insert, update or delete. Migration 0103 must be applied BEFORE the build serves traffic: every converted handler calls the new function, so without it every create, update and delete in group 1 answers 500. — **DONE** (migration 0103, `audit/audited-write.ts`, `audit/row.ts`, group-1 route handlers, tests)
