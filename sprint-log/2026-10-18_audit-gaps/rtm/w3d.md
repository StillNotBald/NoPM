# W3-D cross-project dependencies RTM rows (R-147)

## REQUIREMENTS.md bullets

- **R-147** Cross-project dependencies and contingency (audit gap B5; outcome 1, presentable multi-project). A project can declare that it depends on another project (kind `delivery|resource|decision|risk`, optional note, optional linked risk). A project whose declared health is not red or complete but that depends, directly or through other projects (up to 5 hops), on a red project is shown as "contingent" in the portfolio. Acceptance: (a) migration 0099 adds `project_dependencies` (workspace_id, project_id, depends_on_project_id, kind CHECK, `linked_risk_id` FK to risks ON DELETE SET NULL, note, created_by, created_at, updated_at), CHECK `project_id <> depends_on_project_id`, unique `(project_id, depends_on_project_id, kind)`; a trigger refuses a dependency whose projects or linked risk are in another workspace (`CROSS_WORKSPACE`); a trigger refuses a loop A to B to A of any length and kind (`DEPENDENCY_CYCLE`, recursive walk, per-workspace advisory lock); `trg_project_dependencies_updated`; RLS select-only, insert/update/delete revoked from browser roles; no backfill; (b) `GET /api/projects/:id/dependencies` (scope `project:read`) lists both directions with the other project's code, name and declared RAG; `POST` (scope `project:write`) adds one: self-dependency 422 `self_dependency`, project or risk from another workspace 422 `invalid_reference`, risk not in either project 422 `risk_not_in_projects`, loop 422 `circular_dependency`, same link and kind twice 409 `duplicate_dependency`; `DELETE /api/projects/:id/dependencies/:depId` (scope `project:write`) removes one; each write writes one audit row `project.dependency.add` / `project.dependency.remove` with before and after; a locked project may still gain or lose dependencies because the locked schedule is not changed; (c) `GET /api/projects/:id/contingency` (scope `project:read`) returns the declared RAG, the worst declared RAG among its dependencies (transitive, depth 5, cycle-safe), `contingent_on_red` and the chain of projects that causes it; it is advisory and never changes a declared RAG; (d) `computeContingentOn` in `program-rollup.ts` feeds an amber "Contingent" marker with a tooltip naming the red project in the Portfolio roadmap, the Mainline feed (`GET /api/timeline`) gains `projectDependencies` plus milestone-to-milestone `dependency` edges, and the Network lens lists the project dependencies, so its "cross-project dependency graph" caption is true; same-project task edges are unchanged; (e) the project page gains a "Project dependencies" panel (list, add with project, kind and risk pickers, remove; stacked rows at phone width). Migration 0099 must be applied BEFORE the build serves traffic: the Portfolio page and the Mainline feed read the new table, so without it both show a load error. — **DONE** (migration 0099, `api/projects/[id]/dependencies/**`, `api/projects/[id]/contingency`, `project-contingency.ts`, `program-rollup.ts`, portfolio page and roadmap, `timeline/gather.ts`, Network lens, `project-dependencies-panel.tsx`, tests)
