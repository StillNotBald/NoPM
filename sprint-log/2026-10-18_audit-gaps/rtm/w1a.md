- **R-127** Lock integrity (audit gaps M7 + K3). Every locked project records who locked it and when, whoever the actor was. Acceptance: (a) migration 0088 adds `projects.locked_by_actor_type` (`user|token`), `locked_by_actor_id` and `locked_by_label`; `locked_by` stays the profile FK and holds the human (the user, or `api_tokens.created_by` for a token); (b) CHECK `projects_lock_integrity` (`is_locked = false OR (locked_at IS NOT NULL AND locked_by_actor_id IS NOT NULL)`), added NOT VALID, backfilled from the latest `project.lock` audit row per project (locks with no audit row are stamped as a legacy lock, never an invented person), then validated; (c) `nopm_lock_project` is recreated and always sets the actor columns, and any other overload is dropped; a trigger clears the locker on unlock; (d) Q-GOV-10 holds: lock = manager, admin or a write token, unlock = a manager or admin in person, never a token, and the 403 text says who may unlock; (e) `GET /api/projects/:id` returns the locker columns and the project page badge reads "Locked by <label>". Migration 0088 applies BEFORE the build deploys. — **DONE** (migration 0088, lock-permissions, project page badge, tests)
- **R-128** Four-eyes backfill, validation and legacy audit trail (audit gap G6 caveats). The database can prove no historical self-approval, and the one remaining legacy pass is listed in the audit trail. Acceptance: (a) migration 0089 backfills `requested_principal_id` on change_requests and deletion_requests (and the timesheet submitter principal) for every row still NULL, from the requester profile, `api_tokens.created_by`, or the earliest audit row, and logs in a NOTICE how many cannot be derived; (b) `cr_principal_distinct`, `deletion_principal_distinct` and `ts_principal_distinct` are each validated in their own exception block that skips with a NOTICE, so the migration never blocks a release; (c) deciding a request whose requester principal is NULL still passes (it would otherwise strand the request) but writes a fail-soft `four_eyes.legacy_requester_unknown` audit row on deletion approve, deletion reject and change-request decision; new rows still fail closed at raise time. — **DONE** (migration 0089, `decide.ts`, audit glossary, tests)
