# RTM rows - cycle 2 builder B: tier engine (Q1, Q4, Q5)

## Payload contract for the UI (builder C reads this)

Every change request payload (list, detail, project list, review items, MCP) carries:

- `tier`: one of `routine | normal | high_risk | emergency | strategic`.
- `is_emergency`: boolean, true exactly when `tier` is `emergency`. The UI flags a request when either is set.
- An emergency request commits when raised. Its `status` is `approved` at raise time (later `implemented` once someone marks it live). It has no `decided_by*` fields, `decision_rationale` reads "Emergency: committed on raise, no approval required (owner decision Q1)", and it never appears as waiting for a decision.
- `retro_due_at`: always `null` for emergencies raised after this cycle (deprecated, kept for old rows).
- `retro_decided_at`: set (to the raise time) on every emergency, so nothing reads as "owed a retro decision" (deprecated).
- `retro_outcome`: `not_required` for emergencies raised after this cycle, `retired` for emergencies that were waiting for a retro decision when migration 0106 ran; older decided rows keep `approved | rejected`. (deprecated)
- Review payload (`GET /api/review`): `retro_overdue` and `retro_due_at` are REMOVED from the review item (corrected in cycle 2 review C2-14). `tier` is `"emergency"` and `is_emergency` is true on emergency items, and an emergency never appears as waiting.
- Status `emergency` is no longer produced. Old rows are moved to `approved` by 0106. UI code may stop special-casing it.
- Deletion requests: `tier` is `high_risk` for an expense whose amount reaches the workspace currency threshold, `normal` for an approved document.
