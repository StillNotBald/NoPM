# W2-D mcp-reads RTM rows (R-139)

## REQUIREMENTS.md bullets

- **R-139** Decision-prep reads over MCP (audit gap B7). An AI assistant can read what it needs to prepare a decision, through MCP and the in-app assistant, without any way to decide. Acceptance: (a) new GET-only tools `list_change_requests`, `get_change_request`, `list_decisions`, `get_document`, `get_evm` are in the shared registry, so both the MCP server and the assistant get them; (b) new routes GET `/api/change-requests` (scope `change:read`) and GET `/api/decisions` (scope `decision:read`) list workspace-wide, newest first, filtered by `project_id` and `status`, paged (limit capped at 100), lean by default with `view=summary|full` and `fields=` from the allow-lists in `web/src/lib/api/views.ts`; a bad `status`, `project_id`, `view` or `fields` is 422; (c) new route GET `/api/projects/:id/evm` (scope `budget:read`) returns BAC, PV, EV, AC, committed, CV, SV, CPI, SPI, EAC, ETC, VAC computed by `web/src/lib/evm.ts` from the same inputs as the Budget page (expenses, baseline dates, workspace-zone date), plus `schedule_basis`; (d) `get_document` returns the document row (metadata, `external_url`, stored text body) and never file bytes; (e) every query filters by `actor.workspaceId`; a token without the read scope gets 403; (f) the assistant scope ceiling gains only `decision:read` and `document:read`, never a decide, approve or write scope; (g) `web/mcp/README.md` lists the tools; (h) the two list routes select the wave-2 columns (`impact_scope`, `implemented_at`, `change_request_id` and so on) through `views.ts`, so migrations 0092, 0093 and 0094 must be applied before the build serves traffic; (i) GET `/api/documents/:id` selects an explicit column list that omits `storage_path`. Outcome: easier reporting. — **DONE** (routes, tools, scopes and tests shipped in wave 2; OpenAPI and llms.txt entries applied by the docs agent per `rtm/w2d-openapi-notes.md`)
