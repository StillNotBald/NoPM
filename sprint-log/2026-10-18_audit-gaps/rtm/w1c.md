- **R-132** Access review export - members, tokens, connector identities (audit M5, CR-2026-10-18-01). Acceptance: (a) GET `/api/export?entity=members|tokens|identities` returns a CSV only to an admin or manager SESSION (a token with any scopes, a member or a viewer gets 403 and nothing is read); (b) members: id, display_name, email (the audience and field `GET /api/members` already serves), role, status, `mfa_enabled`, `created_at`, `removed_at`, last role change (from `member.role_change` audit rows); (c) tokens: id, label, prefix, scopes, creator id and name, `created_at`, `expires_at`, `revoked`, `last_used_at`, never the hash, assistant per-turn tokens hidden (there is no `revoked_at` column, the flag is exported); (d) identities: profile, provider, connector, `linked_at`, `revoked_at`, never the external user id; (e) "Export people", "Export chat links" buttons on the People page and "Export tokens" on the API Tokens page; (f) every export writes the existing `export.csv` audit row with the entity name. No migration. — **DONE**
- **R-133** Export date ranges on every entity and audit CSV provenance columns (audit M3, export half). Acceptance: (a) `from` / `to` (UTC days, inclusive, malformed ignored) narrow every export entity on `created_at`, or on `updated_at` with `on=updated` where the entity has one (identities use `linked_at`); the range is recorded in the `export.csv` audit row; (b) the audit CSV gains `principal_id`, `principal_label` (resolved from profiles in one query, no per-row lookups), `via_connector_id`, `external_event_id`, `external_actor_ref`; (c) the 10,000-row cap and the truncation note are unchanged; (d) documented in `web/src/app/api/export/README.md`. No migration. — **DONE**
