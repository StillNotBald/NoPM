# Decisions — 2026-09-07 open-source release

| # | Decision | Rationale | Alternatives rejected |
|---|---|---|---|
| D1 | **Everything in the repository is open source under Apache-2.0.** Premium = services only: paid Implementation Guide, change requests / custom work, optional hosted setup and team training. | The project thesis ("governance you can verify by reading the code") collapses if any governance code is withheld. The code has no clean seam to split on: governance is threaded through every route via the shared `route()` wrapper, not a separable module. Splitting would also require history surgery for zero benefit. The maintainer's stated monetization (guide + CRs) is services, which needs no code split. | Open-core with premium modules (SSO, multi-tenant admin, board-pack reporting, DR kit, integrations, hosted BYOK vault, compliance exports). None of these exist today; they remain only a *future* paid-module menu in the feature inventory, not removals. |
| D2 | **License switch MIT → Apache-2.0**, root `LICENSE` (canonical text, diffed byte-for-byte against apache.org) + `NOTICE` + `license` field in all three `package.json`. No per-file headers. | Apache-2.0 adds an explicit patent grant and a NOTICE mechanism; both matter more once strangers deploy it commercially. Per-file headers are an ASF convention, not a license requirement, and would be a large low-value diff. | Keep MIT (simpler, but no patent grant). Dual license (unnecessary for a solo maintainer). |
| D3 | **No CLA.** Contributions are accepted under the inbound=outbound assumption of Apache-2.0 §5; DCO sign-off may be added later if contribution volume warrants. | A CLA deters casual contributors and buys a solo maintainer nothing. | CLA bot. |
| D4 | **Trademark carve-out in README** ("NoPM", "stillnotbald"), no registration. | Apache-2.0 §6 already excludes trademarks; a plain README section removes ambiguity at no cost. | Formal registration (not warranted for a portfolio project). |
| D5 | **Recreate the GitHub repository from a fresh clone before flipping public** (maintainer-executed; see `PUBLISH_RUNBOOK.md`). | 18 of 19 pre-purge commits are still fetchable on GitHub by SHA 25 days after the purge, one of them listing a private research file. Only a repo that never received those objects is provably clean. | GitHub Support GC ticket (slower, unverifiable from outside; fallback only if the URL cannot be reused, but the rename trick keeps the URL anyway). |
| D6 | **Document attachments: normalize + verify, do not reject.** Executable types (HTML/SVG/XML/JS) are coerced to `application/octet-stream`; inline-rendered types (PDF/PNG/JPEG/GIF/WebP) must match magic bytes on attach (422 otherwise); every other type is served as a download. | Keeps the product promise "PDF, images, or any file type" while closing the spoofed-PDF-in-iframe surface (security F3). A strict allow-list would have broken the promise and the UI copy. | Strict MIME allow-list (rejects legitimate office/zip files). `sandbox` on the iframe (blocks Chrome's PDF viewer). |
| D7 | **Keep `sprint-log/` public, reworded, not pruned or relocated.** | Dated build receipts are the evidence for the project's claims. Only tone needed fixing: internal tool names and second-person notes. Honest admissions (DR drill not yet executed, accidental deploy postmortem) stay. | Move to `docs/history/` with a disclaimer; delete the corpus. |
| D8 | **`docs/product/PRODUCT.md` stays, trimmed to product-facing language with a "planning voice" banner.** | Internal planning notes do not belong in a public product brief; the rest is legitimate product framing. | Delete the file; rewrite wholesale. |
| D9 | **Commit, push, repo creation, visibility flip, deploy, and old-run-log cleanup are maintainer actions.** The assistant leaves the working tree ready and the runbook exact. | All outward-facing and hard to reverse; the harness is also blocked from `vercel deploy`. | — |
