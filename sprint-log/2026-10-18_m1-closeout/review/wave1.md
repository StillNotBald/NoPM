## Checked and clean (no finding)

- **Additive only.** 0107, 0109 and 0110 create functions and nothing else. 0108 adds one table (`create table if not exists`, seed `on conflict (entity) do nothing`, RLS on, no policy, revoked from public, anon and authenticated) and seven functions. 0111 adds two nullable columns with `add column if not exists` and a CHECK added `not valid`, then validated inside `exception when others then raise exception`, so a failed validation stops the migration instead of printing a notice. No existing row is rewritten.
- **No signature change.** All 22 function names are new. No earlier migration defines any of them, so `create or replace` never meets a changed return type, and no overload can make a PostgREST call ambiguous.
- **Definer, pinned path, revoked.** All 22 functions except the two helpers in W1-05 are `security definer` with `search_path = public`. Each has `revoke execute ... from public, anon, authenticated` and a grant to `service_role` only (0107 lines 118-119; 0108 section 9; 0109 lines 646-668; 0110 after each function).
- **No caller JSON in dynamic SQL.** The only dynamic SQL is W1-04's `execute`. Everything else reads `p_input`, `p_patch` and `p_updates` with `->>` into typed columns.
- **Action names, target types, before and after, row counts.** I diffed the old `writeAudit` calls against the SQL for change-request create, update and delete, rebaseline create, the seven `*.delete_requested`, withdrawn and rejected, the four MFA transitions, Lark connector create and update, GitHub create, update (two rows when rules change) and revoke, the invite sweep (one row per invite), identity link and blocked, clash auto-resolve, overspend, snapshot (one row per workspace run), and weekly report. All match. Disclosed differences only: the MFA `backup_codes` now `{}` instead of null, the link code is no longer burned after a lost duplicate race, the weekly report `recipients` is the claimed count, and the project deletion snapshot is taken under a key-share lock in SQL.
- **No secret reaches an audit row from SQL.** MFA functions take the encrypted secret and the SHA-256 hashes as separate arguments and write neither to `audit_log`. Connector audit views carry presence flags and masked ids only, and `secret_enc` and `relay_secret_hash` never appear in them. The GitHub payload is `{kind, name, status}` plus a `secret_rotated` flag. Returning the full connector row to the route is what `CONNECTOR_COLUMNS` already did.
- **MFA attempt counter.** `spendMfaAttempt` is a separate `nopm_rate_check` call made before the audited function and is never refunded on success or failure. A failed audit rolls back the state change and the backup-code burn but cannot reset or skip the counter. The TOTP step burn also stays outside, so a failed audit only costs the user a wait for the next code.
- **No leftover write after the RPC.** In every converted route the calls after the function are notifications, announcements, cookies or approval-card catch-up, not governed writes.
- **Workspace isolation (token actors).** Every target-row statement filters by `p_workspace_id`: change requests, deletion requests, projects, connectors, invites, identity codes, identities, clashes, project budget, snapshot rows (joined to the workspace's projects), weekly recipients. MFA functions require the user to be a profile of that workspace. Identity link filters the connector, the code and the profile by workspace.
- **Unknown SQLSTATE.** `unwrap` and the per-route maps end in a plain `Error` (500). 22P02 is mapped by the route wrapper as before. A build deployed before the migration gets a 500 (function not found), which is why the release order 0107, 0108, 0109, 0110, 0111, then deploy matters.
