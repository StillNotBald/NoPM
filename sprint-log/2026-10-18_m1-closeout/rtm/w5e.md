- **R-168** Anchor the chain head outside the database. Acceptance: (a) the head of each workspace's audit chain (`chain_seq`, `head_hash`, `row_count`, time) is written to a second database reached by `NOPM_ANCHOR_DB_URL` through a pluggable sink (`AnchorSink`: `put`, `latest`; Postgres implementation plus a no-op), one short-lived connection per call with a 5 second connect timeout and a 5 second statement timeout, TLS always on (off only for a loopback host together with `NOPM_ANCHOR_ALLOW_PLAINTEXT_LOOPBACK=1`, set by the local rehearsal only), and every write is read back and compared before it counts as anchored; (b) order everywhere: verify, record the verify result, then anchor the head that includes the verify row; a head already anchored is skipped; (c) a routine success writes no `audit_log` row; the first anchor of a workspace and the first success after a failure streak write one `audit.anchored` row, after the sink confirmed; (d) with `NOPM_ANCHOR_DB_URL` unset nothing is written, nothing is read and nothing throws, and every surface says "not anchored"; (e) nothing is anchored while the state is `mismatch` or the verification failed; (f) a unique conflict on `(workspace_id, chain_seq)` reads the stored record and compares: a different hash is `mismatch`, not a failed insert; (g) `pg` is imported only in `postgres-sink.ts`; the connection string is read in one place and never logged or returned; (h) the daily scheduler step verifies only the rows since the last anchor, anchors only when that check is ok, opens one connection to read the newest anchors of all workspaces, has an 8 second budget inside the 40 second deadline, and after the first failed write marks the remaining workspaces failed without further attempts; (i) there is no manual anchor route. Outcome: easier reporting. — **DONE**
- **R-169** Verify compares the live chain with the latest anchor. Acceptance: (a) `GET /api/audit/verify` adds `anchor: { state, chain_seq, anchored_at, row_count, rows_behind, since }` where `state` is `not_anchored`, `anchored`, `behind` (informational), `mismatch` (the live head is below the anchored `chain_seq`, or the live row at that position is missing or has a different hash) or `unreachable` (the outside copy could not be read or written); (b) `mismatch` makes `ok` false, writes `audit.anchor_mismatch` once per streak (not once per verify), and the plain chain result stays in `chain_ok`; (c) `all_clear` is true only when `ok` is true and the state is neither `mismatch` nor `unreachable`; "anchored" is reported only after a comparison or a confirmed read-back; (d) `audit.verified.after` gains `chain_ok` and `anchor` (state, chain_seq, anchored_at, rows_behind before this verify) so the trail records the anchor state at every check; (e) the five-minute throttle and the bounded window are unchanged, and a throttled call touches nothing; (f) tests cover: anchored, behind, rows deleted, a flipped hash, the chain regrown to the same `chain_seq` with different hashes, an unreachable sink, a failed put, a unique conflict, a chain that does not verify; (g) the audit pack data gains `anchor` and a one-line `anchorLine()` ("Anchor: not anchored / anchored <time> (n rows) / MISMATCH ... / unreachable"), `not anchored` when the variable is unset; the weekly report and PDF are unchanged. Outcome: easier reporting. — **DONE**
